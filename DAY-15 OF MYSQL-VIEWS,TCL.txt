   it is stored in select statement, it looks the behaves of like regular table when the query it 
   you can select from it ,filter it , and join it, but it doesn't store the data 
 2. WHY DO WE NEED VIEWS?
====================
A. Simplify the complex queries: it Hide the multi-table joins, subqueries and calculation behind a single,simple table like name.
  it resuse query logic: Write the complex select once reuse it anywhere ,reports applications,dashboard,without copy of pasting sql.
Data security: expose only the specific columns or rows to certain users, without of granting them accessing to full base table.
different perspectives of the same data : It is Different departments can have the their own taileerd views understialying table.
logic and independence : If the iunderlying table structures changes slightly, you can often adjust the jud=st once.
Simplifying reporting: pre-packages aggregations(total,averages,counts) into a view so business users can query them without knowing the sql.


Advantages
=============
Security:
---------
 Resists access to sensitive columns(eg: salary) or sensitive rows(only a user own department)
Simplicity:
-------------
 end of the users applications interest with simple named virtual table instead thecomplex sql.
1. Reusability
--------------
A view can be created once and used many times instead of writing the same query repeatedly.
2. Consistency
--------------

A view provides the same definition and logic whenever users access it.

Example:
If the company defines “IT employees” using one view, everyone gets the same filtered result.

3. Maintainability
------------------

If a complex query needs to be changed, we can update the view instead of changing the query in many different applications or reports.

Interview: “Views make SQL code easier to maintain because common logic can be centralized.”

4. Custom Data Presentation
---------------------------

A view can show only the columns and rows required by a particular user or department.
5. No Extra Storage Cost
-------------------

A normal view generally stores the query definition, not a separate copy of the underlying table data.

Creating Viwes:
===============
syntax:
------
create view view_name as
select columns
from tables
where conditions;


Altering view:
==============
syntax:
------
alter view view_name as
select new columns
from new tables
where new conditions;


Dropping view:
=================
syntax
-----
drop view view_name;

or 

drop view if exists view_name;

TCL (Transaction control language):
==================================
Transactions: The process of combining all related operation into a single units in executing them a according to the rule of "either all operations should succeed or none should succeed" is called the transaction management.

Examples:
-------
funds transfer
consider a money transfer from process between two accounts.

1. Debit amount from the senders account
2. credit amount into the receiver's account

There are two types of transaction:

1. local Transaction:
--------------------
In local transactions are all operations of a Transaction are executed on the same databases.

examples:
-------
funds transfer from the account to another account where both account belong to the same bank.


2.global Transaction
-------------------------
 A global Transactions ,operations  of a Transactions are executed on different databases.
example:
-------
 funds transfer from one account to  another account where both accounts belongs to different banks.
